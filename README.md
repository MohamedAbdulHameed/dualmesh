# dualmesh

**A multiphysics framework for heat transfer, solid mechanics, fluid dynamics, neutron diffusion and general partial differential equations, with the dual mesh control domain method available as one of the discretization options.**

`dualmesh` is a multiphysics framework for **heat transfer**, **solid
mechanics**, **fluid dynamics**, **neutron diffusion** and **general partial
differential equations**. A problem consists of any number of fields (for example
temperatures, displacements, velocities, or quantities defined by the user),
each governed by a
conservation law written as a sum of named terms. Every term may depend on
every field. All the fields are solved together as one monolithic system by
Newton's method, with an exact Jacobian computed by automatic differentiation.
The same problem description is discretized, by changing one keyword, with the
Galerkin **finite element method**, the vertex-centered or cell-centered **finite
volume method**, or the **dual mesh control domain method** (DMCDM) of
J. N. Reddy. The core is written in C++17 and is driven from Python.

A model is described in physical terms: **physics** such as `heat_transfer`,
`solid_mechanics` and `incompressible_flow`, their **boundary conditions**,
and **couplings** such as `thermal_expansion`. Each physics generates the
**kernels**, **property objects** and boundary conditions of its equations, which
follow the object model of the [MOOSE framework](https://mooseframework.inl.gov)
and are registered objects with validated and self-documenting parameters. An
equation without a physics is written with these objects directly. Meshes are generated by the library or read from
standard file formats, and the solvers are shared by every physics.
[`docs/scope.rst`](docs/scope.rst) describes the coverage of the framework and
compares it with MOOSE and COMSOL Multiphysics.

A two-dimensional bus bar with internal heat generation, fixed temperatures on
two sides and convection on the top (Example 5.4.3 of Reddy's book) reads:

```python
import dualmesh as dm

mesh = dm.generate_rectangle_mesh(x_min=0.0, x_max=0.1, y_min=0.0, y_max=0.05, num_x_elements=10, num_y_elements=5)

problem = dm.Problem(mesh, method="dmcdm")  # or method="fem"
heat = problem.add_physics("heat_transfer", "heat", thermal_conductivity=20.0, heat_source=1.0e6)
heat.add_boundary_condition("Dirichlet_boundary_condition", "left", value=40.0)
heat.add_boundary_condition("Dirichlet_boundary_condition", "right", value=10.0)
heat.add_boundary_condition("convective_heat_flux_boundary_condition", "top", heat_transfer_coefficient=75.0)
problem.solve()

problem.sample("temperature", [[0.05, 0.0]])  # 83.142 (Reddy, Table 5.4.3)
problem.total_reaction("temperature", "left")  # heat flow through the left face
problem.write_vtu("bus_bar.vtu")
problem.write_csv("bus_bar.csv")  # nodal values, with units in the column names
```

A boundary condition named after a side set of the mesh acts on that side set.
The complete script, with post-processors and output files, is
[`examples/bus_bar.py`](examples/bus_bar.py).

## Uncertainty quantification

The `dualmesh.uq` package propagates input uncertainties through any model,
computes Sobol' sensitivity indices, builds Gaussian process surrogates and
calibrates model parameters against measurements.

## The dual mesh control domain method

The **primal mesh** is a mesh of finite elements, which provides the
interpolation of the unknowns. The **dual mesh** is the set of node-centered
*control domains* obtained by joining the edge midpoints, the face centroids
and the element centroids. The governing equation is satisfied in the
integral sense over each control domain, without a weight function:

$$
-\oint_{\partial CD_I} \mathbf{F} \cdot \mathbf{n} \, dS + \int_{CD_I} S \, dV = 0,
$$

where $CD_I$ is the control domain of node $I$, $\mathbf{F}$ is the flux, $S$
is the source and $\mathbf{n}$ is the outward unit normal. The secondary
variables (fluxes, forces and moments) appear on the interfaces of the control
domains, as in the finite volume method, and the gradients on these interfaces
are evaluated from the finite element interpolation, so that no gradient
reconstruction is needed. Every equation in the library is written in the
canonical form $-\nabla \cdot \mathbf{F} + S = 0$, which allows the same
kernels to be discretized by every method.

## Features

- **Methods**: Galerkin finite elements, vertex-centered and cell-centered
  finite volumes, and the dual mesh control domain method, selected by one
  argument. An element type or a physics that a method cannot treat correctly
  is refused with an explanation.
- **Elements**: `Edge2`, `Edge3`, `Tri3`, `Tri6`, `Quad4`, `Quad8`, `Quad9`,
  `Tet4`, `Tet10`, `Hex8`, `Hex20`, `Hex27`, `Wedge6` and `Pyramid5`, mixed
  freely in one mesh, in one, two and three dimensions.
- **Coordinate systems**: Cartesian, axisymmetric ($2 \pi r$) and spherical
  ($4 \pi r^2$).
- **Heat transfer**: conduction with temperature-dependent conductivity,
  volumetric heating, heat capacity, convection by a computed flow, and
  prescribed temperature, flux, convection and radiation boundary conditions.
- **Solid mechanics**: elasticity in plane stress, plane strain,
  axisymmetric and three-dimensional form with thermal strain, tractions and
  pressures, small or finite strain and creep. The structural members are
  mixed Euler-Bernoulli beams, displacement and mixed Timoshenko beams,
  axisymmetric circular plates and rectangular plates, with functionally
  graded sections and the von Kármán nonlinearity.
- **Fluid dynamics**: Stokes and Navier-Stokes flow, by the penalty
  formulation with a recovered pressure, by a stabilized equal-order
  pressure-velocity formulation (PSPG and SUPG), or with Taylor-Hood
  elements, and buoyancy in the Boussinesq approximation.
- **Neutron diffusion**: multigroup diffusion with any number of groups,
  scattering between all groups, vacuum and albedo boundary conditions, and
  the effective multiplication factor and fundamental mode from
  `Problem.solve_eigenvalue()`, verified against the two-dimensional IAEA PWR benchmark.
- **Equations by their coefficients**: the `coefficient_form_PDE` physics
  for a scalar equation with diffusion, convection, absorption and source
  coefficients.
- **Framework objects**: diffusion, anisotropic diffusion, reaction,
  advection, body force, time derivative, coupled force, Dirichlet, Neumann
  and Robin conditions, point sources, constant, function and parsed properties, and expressions
  such as `"sin(pi*x)*exp(-t)"` compiled to C++.
- **Coupled problems**: monolithic and fully coupled, verified on the natural
  convection benchmark of de Vahl Davis (Nusselt numbers within 0.2%).
- **Solvers**: Newton's method with exact Jacobians from forward-mode automatic
  differentiation, direct (Picard) iteration with relaxation, load stepping,
  and steady and transient executioners (the theta method with adaptive time
  steps). Linear systems are solved by a direct solver where a factorization
  is inexpensive and otherwise by the conjugate gradient method or BiCGSTAB
  with an algebraic multigrid preconditioner, chosen automatically, or by
  PETSc (optional at build time) with any of its Krylov methods and
  preconditioners. Factorizations and multigrid hierarchies are reused while
  the matrix does not change.
- **Parallel execution**: threaded assembly, and an MPI solver with a
  two-level overlapping Schwarz preconditioner whose iteration count does not
  grow with the number of processes.
- **Quadrature per kernel**: Gauss rules, midpoint, trapezoid, Simpson, nodal
  lumping, interface and control-domain trapezoid rules, and selective reduced
  integration for locking and penalty terms.
- **Meshing**: generators (line, rectangle, box, annulus, graded spacing),
  local and uniform refinement, and readers for Gmsh, Exodus, VTK, Abaqus and
  other formats through [meshio](https://github.com/nschloe/meshio).
- **Uncertainty quantification**: sampling, Sobol' indices, Gaussian process
  surrogates and Bayesian calibration of one or several experiments
  (`dualmesh.uq`).
- **Results and output**: every study takes `report="full"` (the default),
  `"summary"` or `"none"`. Every result has `summary()`, `to_dict()`,
  `write_json(path)` and `write_csv(path)`, with the units in the column
  names. A `dm.Output` group writes the fields of a run as VTU (with a
  ParaView collection for a transient) and CSV at the output times or interval
  that you give.
- **Extensible from Python**: kernels, boundary conditions and property objects can be
  written in Python and are differentiated exactly.
- **Command-line tools**: `dualmesh list` and `dualmesh describe <type>` for
  the object reference, and `dualmesh mesh <file> --sidesets <file.vtu>` to
  check the side sets of a mesh file.

## Verification

Every worked example of Reddy's book with published dual mesh results is
reproduced by the test suite: one-dimensional and two-dimensional conduction,
axisymmetric conduction, advection-diffusion at high Péclet number, nonlinear
conduction, plane elasticity, pressurized cylinders, squeezed flow, the
lid-driven cavity at Re = 0 and Re = 1000, functionally graded beams (linear and
von Kármán), circular plates and rectangular plates. Natural convection is
checked against de Vahl Davis (1983), and a manufactured-solution study checks
the convergence order of every method and element type. See
[`docs/verification.rst`](docs/verification.rst) and `tests/python`. The suite
also cross-checks against OpenFOAM (see `verification/openfoam`).

## Installation

```console
pip install dualmesh-multiphysics        # binary wheels from PyPI
pip install "dualmesh-multiphysics[all]" # with meshio, matplotlib, SymPy, SciPy
```

The distribution on PyPI is called `dualmesh-multiphysics`, but the package is
imported as `dualmesh` and the command is `dualmesh`:

```console
python -c "import dualmesh; print(dualmesh.__version__)"
dualmesh --version
```

From a clone:

```console
pip install .[all]           # build from source
pytest                       # run the verification suite
```

Building from source requires a C++17 compiler, CMake 3.18 or later and
Python 3.9 or later. Eigen and pybind11 are used if installed and are
downloaded otherwise.

Documentation: <https://dualmesh.readthedocs.io>
