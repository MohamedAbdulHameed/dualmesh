Getting started
===============

This page solves a complete problem and then explains each of its components.
The problem is Example 5.4.3 of the book: a bus bar of 0.10 m by 0.05 m
carrying enough current to generate :math:`10^6\ \mathrm{W/m^3}`, held at
:math:`40\ ^\circ\mathrm{C}` on the left and :math:`10\ ^\circ\mathrm{C}` on the
right, insulated at the bottom, and cooled on top by air at
:math:`0\ ^\circ\mathrm{C}` with a film coefficient of
:math:`75\ \mathrm{W/(m^2\,K)}`.

.. code-block:: python

   import dualmesh as dm

   # 1. a mesh
   mesh = dm.generate_rectangle_mesh(x_min=0.0, x_max=0.1, y_min=0.0, y_max=0.05, num_x_elements=10, num_y_elements=5)

   # 2. a problem on that mesh
   problem = dm.Problem(mesh, method="dmcdm")

   # 3. the physics: heat conduction with a heat source
   heat = problem.add_physics("heat_transfer", "heat", thermal_conductivity=20.0, heat_source=1.0e6)

   # 4. the boundary conditions, named after the sides they act on
   heat.add_boundary_condition("Dirichlet_boundary_condition", "left", value=40.0)
   heat.add_boundary_condition("Dirichlet_boundary_condition", "right", value=10.0)
   heat.add_boundary_condition("convective_heat_flux_boundary_condition", "top", heat_transfer_coefficient=75.0, ambient_temperature=0.0)
   # the bottom is insulated: a zero natural condition, so nothing to add

   # 5. solve
   problem.solve()

   # 6. results
   print(problem.sample("temperature", [[0.05, 0.0], [0.05, 0.05]]))
   print(problem.total_reaction("temperature", "left"))
   problem.write_vtu("bus_bar.vtu")

The printed temperatures are :math:`83.142\ ^\circ\mathrm{C}` and
:math:`76.859\ ^\circ\mathrm{C}`, which agree with the values of Table 5.4.3 of
the book to every printed digit.

Meshes
------

A mesh can be generated by one of the built-in generators:

.. code-block:: python

   dm.generate_line_mesh(start=0.0, end=1.0, num_elements=20)
   dm.generate_rectangle_mesh(x_min=0, x_max=2, y_min=0, y_max=1, num_x_elements=20, num_y_elements=10, element_type="Tri3")  # or "Quad4"
   dm.generate_box_mesh(x_min=0, x_max=1, y_min=0, y_max=1, z_min=0, z_max=1, num_x_elements=8, num_y_elements=8, num_z_elements=8)
   dm.generate_annulus_mesh(inner_radius=0.05, outer_radius=0.1, num_radial_elements=8, num_angular_elements=19)

Non-uniform spacing is specified either as a bias (the ratio between successive
element lengths) or as explicit coordinates:

.. code-block:: python

   dm.generate_rectangle_mesh(x_coordinates=[0, 0.5, 1.5, 3.0], y_coordinates=dm.graded_coordinates(0, 1, 10, bias=0.8))

A mesh written by another program can also be read, e.g., a Gmsh, Exodus, VTK
or Abaqus file, or any other format that
`meshio <https://github.com/nschloe/meshio>`_ supports:

.. code-block:: python

   mesh = dm.read_mesh("channel.msh")  # physical groups become side sets
   mesh = dm.read_mesh("bracket.e")

Side sets and node sets carry the names used in the boundary conditions.  The
generators create ``left``, ``right``, ``bottom``, ``top``, ``back``, ``front``
(and ``inner``, ``outer``, ``start``, ``end`` for an annulus), and the physical
groups of a file keep their names.  Further sets can be defined by a geometric
predicate:

.. code-block:: python

   mesh.add_nodeset_by_predicate("centre", lambda x, y, z: abs(x) < 1e-12)
   mesh.add_sideset_by_predicate("hot_wall", lambda x, y, z: y > 0.999)

Physics, boundary conditions and objects
----------------------------------------

A **physics** names a set of equations in physical terms and creates their
unknowns: ``heat_transfer`` creates the variable ``temperature``,
``solid_mechanics`` the displacements and ``incompressible_flow`` the
velocities.  A **boundary condition** of a physics either prescribes the
variable (``Dirichlet_boundary_condition``, ``fixed_constraint``,
``symmetry_boundary_condition``) or prescribes the normal flux
(``Neumann_boundary_condition``, ``Robin_boundary_condition``,
``convective_heat_flux_boundary_condition``, ``traction_boundary_condition``,
``pressure_boundary_condition``, ...), and it is named after the side set it
acts on.  A **coupling** joins two physics, e.g., ``thermal_expansion``.

Each physics generates registered objects: **kernels**, which contribute a
flux, a source, or both to the equation of one variable, and **property objects**,
which compute named properties, such as ``"stress"``, that the kernels use.
An equation without a physics is written with these objects directly (see
:doc:`user_guide/problem_setup`).

Every physics and every object is created by its registered name and
validated against its declared parameters, so a typo is reported with the
closest name and the list of accepted parameters.  They are listed by:

.. code-block:: python

   dm.list_objects(category="physics")
   print(dm.describe("heat_transfer"))

or, at the command line, by ``dualmesh list`` and ``dualmesh describe
heat_transfer``.

Coefficients can be numbers, named functions, or plain Python callables
``f(x, y, z, t)``:

.. code-block:: python

   heat.add_boundary_condition("Dirichlet_boundary_condition", "top", value=lambda x, y, z, t: 500.0 * (1.0 - 10.0 * x * x))

Solving
-------

.. code-block:: python

   problem.solve()  # steady, Newton
   problem.solve(nonlinear_solver="picard", relaxation=0.35)
   problem.solve(load_factors=[0.25, 0.5, 0.75, 1.0])  # load stepping
   problem.solve_transient(end_time=10.0, time_step=0.5, implicitness=1.0)

Results
-------

.. code-block:: python

   problem.values("temperature")  # one value per node
   problem.sample("temperature", [[0.05, 0.0]])  # anywhere in the mesh
   problem.gradient_at_centroids("temperature")
   problem.property_at_centroids("stress")
   problem.reactions("temperature", "left")  # node by node
   problem.total_reaction("temperature", "left")  # summed
   problem.integrate("temperature")
   problem.write_vtu("out.vtu", cell_properties=["stress"])
   problem.write_csv("out.csv")
   problem.write_mesh_file("out.e")  # through meshio

Comparing the two methods
-------------------------

The only change needed to run the same problem with the Galerkin finite element
method is the ``method`` argument:

.. code-block:: python

   dual = dm.Problem(mesh, method="dmcdm")
   finite_element = dm.Problem(mesh, method="fem")
